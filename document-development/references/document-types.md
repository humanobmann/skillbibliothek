# Document Type Structures

Use these as defaults. Adapt when the user provides a required template.

## Report

Recommended structure:

1. Executive summary
2. Context
3. Current status or findings
4. Analysis
5. Options or scenarios
6. Recommendation
7. Risks and dependencies
8. Next steps
9. Appendix or evidence notes

## Technical Specification

Recommended structure:

1. Title and status
2. Purpose
3. Scope
4. Non-goals
5. Stakeholders
6. Requirements
7. Architecture or design overview
8. Data model
9. Interfaces and integrations
10. Error handling and edge cases
11. Security and privacy considerations
12. Testing strategy
13. Rollout and migration plan
14. Open questions

## Policy or Procedure

Recommended structure:

1. Purpose
2. Scope
3. Definitions
4. Policy statements or rules
5. Roles and responsibilities
6. Procedure steps
7. Exceptions
8. Evidence, records, or audit trail
9. Review cycle
10. Related documents

## Manual or Guide

Recommended structure:

1. What this guide covers
2. Who it is for
3. Prerequisites
4. Quick start
5. Step-by-step instructions
6. Examples
7. Troubleshooting
8. FAQ
9. Reference section

## Proposal

Recommended structure:

1. Summary
2. Problem or opportunity
3. Goals
4. Proposed solution
5. Scope
6. Deliverables
7. Timeline
8. Budget or resources
9. Risks
10. Success criteria
11. Decision requested

## Decision Paper

Recommended structure:

1. Decision needed
2. Background
3. Options considered
4. Evaluation criteria
5. Comparison
6. Recommendation
7. Risks and trade-offs
8. Implementation consequences
9. Next steps

## Project Documentation

Recommended structure:

1. Project overview
2. Goals and non-goals
3. Stakeholders
4. Current status
5. Architecture or operating model
6. Workstreams
7. Dependencies
8. Decisions made
9. Risks and issues
10. Runbook or maintenance notes
11. Changelog
