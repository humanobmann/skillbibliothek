# Design System Playbook

## Purpose

Use this reference for broad visual direction, page architecture, token decisions, and product-specific design choices. Prefer task fit over trend fit.

## 1. Start from product behavior

Classify the interface before styling it:

| Product shape | Primary design pressure | Default direction |
| --- | --- | --- |
| B2B SaaS | clarity, trust, product proof | precision minimalism, outcome-first SaaS |
| AI product | state clarity, controllability, latency | structured bento or dark product UI, concrete demos |
| Analytics / operations | scan speed, exceptions, exact values | operational data-dense |
| Finance | trust, irreversible actions, monetary precision | restrained minimal, strong status semantics |
| Healthcare | accessibility, safety, privacy | warm humanist with explicit controls |
| Public service | task completion, plain language, inclusion | neutral institutional minimalism |
| Nonprofit / civic | human outcomes, participation, transparency | warm humanist, authentic documentary emphasis |
| E-commerce | discovery, price, availability, checkout trust | commerce system |
| Editorial | reading, narrative, evidence | editorial narrative |
| Creative portfolio | work first, identity second | editorial or controlled expressive |
| Developer tool | fast trial, code legibility, system states | dark product or technical minimalism |
| Cybersecurity | density, severity, remediation | dark operational UI with restrained status color |
| Beauty / wellness | calm, confidence, booking | soft UI evolution without low contrast |
| Hospitality | imagery, availability, conditions | luxury editorial plus clear booking |
| Consumer mobile utility | thumb reach, platform conventions, state | native or material-inspired system |

## 2. Visual families

### Precision Minimalism

Use when trust, clarity, speed, and longevity matter. Build hierarchy with spacing, type, border contrast, and a small number of surfaces. Avoid the false minimalism of low-contrast gray text and invisible controls.

### Bento Grid

Use when the product has several distinct capabilities that benefit from modular storytelling. Vary spans intentionally. A bento layout is not permission to put every sentence inside a card. Preserve a single logical order when the grid collapses.

### Editorial Narrative

Use for content, reports, campaigns, portfolios, and storytelling. Use large typographic contrast, art-directed imagery, readable measure, captions, and sectional pacing. Avoid repetitive dashboard cards.

### Operational Data Dense

Use for dashboards, admin, monitoring, and professional tools. Optimize scanning and exceptions. Use tabular numerals, predictable alignment, strong filter state, compact but consistent spacing, and stable table geometry.

### Soft UI Evolution

Use for wellness, hospitality, and calm premium services. Use gentle shadows and organic surfaces but keep controls, text, focus, error states, and boundaries explicit. Do not reproduce classic low-contrast neumorphism.

### Neo Brutal

Use selectively for culture, youth, creative campaigns, and deliberately bold identities. Use strong borders, typographic scale, asymmetry, and a limited palette. Keep navigation and task semantics conventional.

### Controlled Glass

Use glass only when translucency explains layering or context. Measure the final composed contrast against actual backgrounds. Provide solid fallbacks for reduced transparency, weak GPUs, and visually noisy imagery.

### Dark Product UI

Use for developer tools, security, media, and high-attention operational contexts when appropriate. Use layered near-black surfaces rather than pure black everywhere. Reserve luminous accents for high-value state or action.

## 3. Anti-pattern filter

Reject these unless a specific product requirement justifies them:

1. Generic purple to pink AI gradient as identity.
2. Sparkle icons as a substitute for explaining AI behavior.
3. Every section inside a rounded card.
4. Three identical feature cards as the default content architecture.
5. Huge gradient headline followed by vague marketing copy.
6. Decorative blobs and noise textures with no hierarchy function.
7. Glassmorphism on every surface.
8. Emoji used as structural icons.
9. Hover-only controls or information.
10. Motion that blocks interaction or hides final state.
11. Low-contrast gray-on-gray minimalism.
12. A chart wall with no analytical priority.
13. Dark mode generated by mechanical inversion.
14. Mobile layouts created by simply stacking desktop columns.
15. Placeholder-only form labels.
16. Destructive confirmation dialogs that say only “Are you sure?”.
17. Truncated chips, badges, or IDs without access to the full value.
18. AI-generated brand marks, logos, or organization names without request.

## 4. Token hierarchy

Create semantic tokens before polishing individual components.

### Color

Use semantic roles such as:

```text
color-bg
color-surface
color-surface-raised
color-text
color-text-muted
color-border
color-primary
color-on-primary
color-accent
color-focus
color-danger
color-success
color-warning
```

Map roles independently for light and dark themes. Do not scatter raw hex values through components.

### Spacing

Derive from a 4 or 8 base rhythm. Recommended families:

- Dense: 4, 8, 12, 16, 24, 32.
- Standard: 4, 8, 16, 24, 40, 64.
- Spacious: 8, 16, 24, 40, 64, 96.

Use density by task. Marketing whitespace should not make a data table unusable. Dashboard compactness should not make touch targets unsafe.

### Type

Define roles rather than arbitrary sizes:

```text
display
h1
h2
h3
body-lg
body
body-sm
label
caption
code/data
```

Keep body text generally at 16px or platform equivalent unless a dense professional context and accessibility testing justify smaller text. Use tabular numerals for monetary, metric, timer, and table values.

### Radius and elevation

Use a small scale. Radius and shadow should express hierarchy, not decoration. A product rarely needs five unrelated card radii and eight custom shadows.

### Motion

Define shared motion roles:

```text
motion-feedback
motion-enter
motion-exit
motion-layout
motion-emphasis
```

Choose timing by distance, complexity, platform, and context. Exits can generally be quicker than entrances. Reduced motion must preserve final state and task comprehension.

## 5. Information hierarchy

Within five seconds a new user should be able to identify:

1. Where they are.
2. What the page is for.
3. What matters most now.
4. What the primary action is.
5. What changed or requires attention.

Use size, position, grouping, contrast, and spacing before adding more color.

## 6. Page patterns

### Outcome-first SaaS

Outcome and CTA -> trust -> workflow -> evidence -> integrations -> commercial detail -> CTA/FAQ.

### Operational dashboard

Context/filter state -> top KPIs -> primary trend -> exceptions/actions -> detail table -> drill-down.

### Service booking

Service promise -> service list -> proof/credentials -> process -> availability -> booking -> location/contact -> FAQ.

### Community participation

Human outcome -> need -> evidence -> ways to participate -> project impact -> transparency -> join/donate/contact.

### Trust and compliance

Value -> credentials/safeguards -> process -> proof -> conditions/policies -> support -> action.

### Editorial story

Title/deck -> lead media -> readable narrative -> evidence/figures -> context modules -> related content -> next action.

### Developer product

One-sentence utility -> install or try -> working example -> capabilities -> docs/integration -> performance/security proof -> commercial or open-source CTA.

## 7. Image direction

Use real, product-relevant imagery when possible. For people-centered products, prefer authentic contexts over posed stock aesthetics. For software, show real interface states instead of abstract 3D devices unless the request is explicitly promotional.

Never invent logos, campaign marks, organization names, seals, or footer branding unless the user requests them.

## 8. Responsive composition

Do not treat responsive design as a set of widths only. Decide what happens to:

- priority and reading order,
- navigation model,
- grid spans,
- table columns,
- filters,
- secondary actions,
- sticky regions,
- long labels,
- charts,
- touch targets,
- safe areas,
- keyboard focus,
- text scaling.

Test at narrow mobile, large mobile, tablet, standard desktop, wide desktop, browser zoom, and enlarged text when relevant.
