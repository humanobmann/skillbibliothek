# Command Playbooks

Use the narrowest playbook that matches the request.

## craft

Treat as new work. Establish product truth, choose one visual world, implement the complete responsive surface, apply the craft floor, and perform bounded QA.

## shape

Do not code first. Produce a compact interaction model: users, primary task, content priority, screen or state map, component regions, responsive behavior, and unresolved product decisions. Move into visual direction only after task structure is coherent.

## init

Capture reusable context when the project lacks it: product purpose, audience, brand lane, voice, key surfaces, platform, accessibility expectations, existing design authority, and anti-references. Prefer updating an existing project context file over creating a parallel truth source.

## document

Infer the incumbent design system from real code and assets. Record typography, color roles, spacing, radii, elevation, layout patterns, component conventions, interaction behavior, and intentional exceptions. Distinguish observed rules from guesses.

## extract

Find repeated patterns used at least several times, duplicated token values, divergent implementations of the same concept, and composition patterns worth centralizing. Extract without flattening legitimate variants.

## critique

Use `evaluation.md`. Focus on design judgment, hierarchy, task clarity, identity, and cognitive load. Rank findings by user impact.

## audit

Use `evaluation.md` plus the optional linter. Focus on verifiable accessibility, responsive, performance, semantic, and robustness risks.

## polish

Do not redesign. Correct alignment, rhythm, typography, inconsistent states, awkward wrapping, visual balance, focus treatment, hover and pressed states, and minor responsive defects. Preserve identity and structure.

## bolder

Increase conviction rather than decoration. Strengthen one or more of: scale contrast, composition, typography personality, imagery, accent use, spatial tension, or interaction emphasis. Keep the primary task obvious.

## quieter

Reduce competing emphasis. Remove redundant borders, badges, cards, decorative icons, shadows, color accents, motion, and copy. Preserve the information and actions users need.

## distill

Challenge every element. Combine duplicated controls, eliminate explanatory copy already implied by structure, flatten unnecessary containers, simplify choice sets, and move advanced options behind progressive disclosure where appropriate.

## harden

Add realistic production states: slow loading, network error, empty data, partial data, permission denied, long names, long translated strings, invalid input, destructive actions, retries, disabled actions, and narrow screens. Prevent layout breakage and ambiguous recovery.

## onboard

Design the fastest path to first value. Prefer contextual guidance and meaningful empty states over long tours. Explain what to do, why it matters, and what success looks like.

## animate

Map motion to state change or feedback. Define trigger, property, duration, easing, interruption behavior, and reduced-motion fallback. Avoid decorative perpetual motion unless the experience explicitly requires it.

## colorize

Start from semantic roles and hierarchy. Introduce color where it communicates brand, state, grouping, or priority. Test every added color in normal, hover, focus, selected, disabled, and error contexts.

## typeset

Review font family, weight availability, type scale, line height, measure, alignment, number formatting, label casing, and responsive wrapping. Improve hierarchy before adding decorative type effects.

## layout

Diagnose structural problems before moving boxes. Fix reading order, grouping, container width, alignment, spacing rhythm, density, and responsive rearrangement. Do not use arbitrary negative margins to conceal structural issues.

## delight

Add a small number of memorable details that reinforce product identity or user accomplishment. Examples include tailored empty-state illustration, precise success feedback, contextual microcopy, subtle state transitions, or a distinctive data treatment. Do not scatter novelty everywhere.

## overdrive

Push composition, typography, imagery, or interaction beyond conventional patterns while preserving usability, accessibility, content truth, and performance. Use this only when the requested experience benefits from spectacle or strong authorship.

## clarify

Rewrite labels and messages around user intent. Prefer concrete verbs. Explain errors with cause and recovery. Remove jargon. Keep destructive consequences explicit. Do not change policy or factual meaning.

## adapt

Use `responsive-native.md`. Recompose for device and input differences rather than shrinking the same layout. Preserve task priority and platform expectations.

## optimize

Find the actual bottleneck before changing aesthetics. Inspect asset weight, unnecessary client rendering, expensive effects, layout shifts, hydration, render frequency, animation cost, and interaction latency. Prefer fixes that improve perceived speed and preserve visual intent.

## live

Treat the selected region as a controlled experiment. Generate a few materially different variants that keep surrounding context fixed. Label the design variable being tested, such as density, hierarchy, composition, type treatment, or color emphasis. Do not vary everything simultaneously.
